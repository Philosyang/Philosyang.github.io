```python
class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        prereq_dict = {}

        for i, j in prerequisites:
            if prereq_dict.get(i, -1) == -1:
                prereq_dict[i] = [j]
            else:
                prereq_dict[i].append(j)

        def search(seen: set, current_course: int) -> bool:
            if current_course in seen:
                return False
            if prereq_dict.get(current_course, -1) == -1:
                return True
            seen.add(current_course)
            return all(search(seen, x) for x in prereq_dict[current_course])

        for k, v in prereq_dict.items():
            if not search(set(), k):
                return False

        return True
```

The issue of this code is that, with our `search()` right now and a diamond/leaf like this: `[0,1], [0,2], [1,3], [2,3], [3,4]`; when we first traverse 0->1->3->4 and we finish, the `seen` never gets reverted appropriately - 1 and 3 are still `seen` to our code, yet since we already reverted back to 0, we should remove 1 and 3 as well.  
Even if we correctly revert this, what is the runtime of our current code? worst case it's O(2^n). Why? Imagine a diamond chain `[A0,B0], [A0,C0], [B0,A1], [C0,A1], [A1,B1], [A1,C1], [B1,A2], [C1,A2]`, how many times will we traverse `A2`? 2^2 times. Every layer doubles. With k diamonds you have 3k+1 nodes and 2^k explorations of the bottom. At 20 diamonds that's 61 nodes and a million; At 30 diamonds that's 91 nodes and a billion.

So how do we fix this? For `[0,1], [0,2], [1,3], [2,3], [3,4]`, if we completed 0-1-3-4, we should mark 1, 3, and 4 as "done since here" - and it's not `seen`, it should be another global flag so that whoever reaches this node again instantly exits. This resolves the issue of the diamond chain issue, if 4 is done and we revisit it, we instantly return True.
